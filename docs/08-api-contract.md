# 08 — API contract (v1)

Base path `/api/v1`. JSON everywhere. All money fields are **integers named `*_pesewas`**. All ids are
UUIDs; client-originated ids are UUIDv7. Times are ISO 8601 UTC. The generated `backend/openapi.json` is
the machine-readable truth; this document is the human summary and the rules the generator cannot express.

---

## 1. Headers

| Header | On | Rule |
|---|---|---|
| `X-Device-Token` | every staff request | opaque token from device enrolment; 401 `device_unknown` / `device_revoked` |
| `Authorization: Bearer` | every staff, guest and owner-API request | staff JWT, guest JWT, or owner session token |
| `Idempotency-Key` | **every `POST`** | UUIDv7 generated by the client per command; 400 `idempotency_key_missing` if absent |
| `X-Client-Time` | every `POST` | the device's clock, stored as `client_created_at`; never used for ordering |
| `Last-Event-ID` | `GET /stream` | last `seq` seen; server replays from there |
| `Idempotent-Replayed: true` | response | set when the response came from the idempotency store |
| `ETag` / `If-None-Match` | `GET /menu` | 304 when unchanged |

Command bodies that need manager authorisation include:

```json
"authorisation": {"token": "<from POST /auth/authorise>", "reason_code": "WRONG_TABLE"}
```

---

## 2. Errors

`application/problem+json`, RFC 9457. `code` is stable and is what clients switch on.

| status | code | When |
|---|---|---|
| 400 | `validation_error` | body fails the serializer; field errors in `errors` |
| 400 | `idempotency_key_missing` | `POST` without the header, or not a UUIDv7 |
| 401 | `device_unknown` `device_revoked` `token_invalid` `token_expired` `session_closed` | auth failures |
| 403 | `role_not_allowed` | principal's role is not in the endpoint's `allowed_roles` |
| 403 | `authorisation_required` `authorisation_invalid` `authorisation_purpose_mismatch` | manager PIN flow |
| 403 | `shift_required` | cashier action with no open shift |
| 404 | `not_found` | includes cross-tenant ids — never 403 |
| 409 | `illegal_transition` | state machine says no; `detail` names status and command |
| 409 | `idempotency_in_progress` | same key, still executing |
| 409 | `unserved_orders` | settlement attempted with unserved food |
| 409 | `table_occupied` `shift_already_open` | uniqueness rules |
| 422 | `idempotency_key_reused` | same key, different request |
| 422 | `item_unavailable` `item_inactive` `modifier_invalid` `required_modifier_missing` | ordering |
| 422 | `overpayment` `discount_exceeds_subtotal` `tendered_insufficient` | money |
| 423 | `pin_locked` | five failures; `detail` carries `retry_after_seconds` |
| 429 | `throttled` | guest rate limit |

## 3. Endpoints

`Roles` lists who may call. `Auth` marks commands that require the `authorisation` block.

### Auth and devices

| Method | Path | Roles | Notes |
|---|---|---|---|
| POST | `/devices/enrol` | (none — enrolment code) | `{enrolment_code}` → `{device_id, device_token, allowed_roles}`. Emits `DEVICE_ENROLLED`. |
| GET | `/devices/me` | staff | device label, allowed roles, staff list for the PIN pad |
| POST | `/auth/pin` | device | `{staff_id, pin}` → `{token, expires_at, staff: {id, name, role}}`. 423 after 5 failures. |
| POST | `/auth/authorise` | staff | `{pin, purpose}` → `{authorisation_token, expires_in}`. PIN must belong to MANAGER/OWNER. |
| POST | `/auth/owner/login` | — | `{email, password}` → `{totp_required: true}` |
| POST | `/auth/owner/totp` | — | `{code}` → session cookie |
| POST | `/auth/logout` | any | ends staff token or owner session |

`purpose` values: `VOID_AFTER_ACK` `DISCOUNT` `COMP` `PRICE_OVERRIDE` `REOPEN` `DRAWER_MOVEMENT`
`PAYMENT_VOID` `PRICE_CHANGE_IN_SERVICE`.

### Menu

| Method | Path | Roles | Notes |
|---|---|---|---|
| GET | `/menu` | staff, guest | full menu: categories → items → modifier groups → modifiers. ETag. Includes `is_available`. |
| POST | `/menu/items/{id}/86` | KITCHEN MANAGER OWNER | emits `ITEM_86ED`; `is_available=false` |
| POST | `/menu/items/{id}/restore` | KITCHEN MANAGER OWNER | emits `ITEM_RESTORED` |
| POST | `/menu/items/{id}/price` | MANAGER OWNER · Auth during service hours | `{price_pesewas}` → `PRICE_CHANGED` |

Menu CRUD (categories, items, modifiers, images) is Django admin in v1.

### Floor and sessions (the bill)

| Method | Path | Roles | Notes |
|---|---|---|---|
| GET | `/tables` | staff | tables with `open_session` summary (id, opened_at, bill_total, paid, order count, state chip) |
| POST | `/sessions` | WAITER MANAGER OWNER | `{id, table_id, party_size}` → 409 `table_occupied` if one is open. Emits `SESSION_OPENED`. |
| GET | `/sessions/{id}` | staff | session + orders + payments + balance |
| GET | `/sessions/{id}/bill` | staff | what the receipt prints: lines (snapshots), discounts, total, payments, balance |
| POST | `/sessions/{id}/close` | WAITER CASHIER MANAGER OWNER | only when settled or every order voided. Emits `SESSION_CLOSED`. |
| POST | `/sessions/{id}/reopen` | CASHIER MANAGER OWNER · **Auth** | reopens a settled/closed bill; alerts owner. Emits `SESSION_REOPENED` + `ORDER_REOPENED`. |
| POST | `/sessions/{id}/guest-token` | WAITER MANAGER OWNER | hands the tablet over: `{mode: "guest"}` → guest JWT |

|---|---|---|---|

### Payments and shifts

| Method | Path | Roles | Notes |
|---|---|---|---|
| GET | `/shifts/current` | CASHIER MANAGER OWNER | the caller's open shift or 404 |
| POST | `/shifts` | CASHIER MANAGER OWNER | `{id, opening_float_pesewas}`. 409 if one is open. `SHIFT_OPENED` |
| POST | `/shifts/{id}/movements` | CASHIER MANAGER OWNER · **Auth** | `{id, kind, amount_pesewas, reason_code, note}`. `DRAWER_MOVEMENT` |
| POST | `/shifts/{id}/close` | CASHIER MANAGER OWNER | `{declared_cash_pesewas, notes}` → response includes `expected`, `variance`. `DRAWER_COUNTED` + `SHIFT_CLOSED` |
| GET | `/shifts/{id}/z-report` | CASHIER(own) MANAGER OWNER | totals by method, movements, expected vs declared vs variance |

### Realtime

| Method | Path | Roles | Notes |
|---|---|---|---|
| GET | `/stream` | staff, owner | `text/event-stream`; see §4 |
| GET | `/events?since=<seq>&limit=200` | staff, owner | polling fallback; same envelopes |

### Guest (sandboxed router — hostile input)

| Method | Path | Notes |
|---|---|---|
| POST | `/guest/sessions/{qr_token}` | `qr` mode: table QR → guest JWT for the table's **open** session (409 if none; the waiter opens it) |
| GET | `/guest/menu` | same shape as `/menu` |
| POST | `/guest/orders` | draft in **its own** session only; `origin` = `GUEST_TABLET` or `GUEST_QR` from the token |
| POST | `/guest/orders/{id}/items`, `/remove`, `/modify`, `/submit` | same rules as staff; `actor_role = GUEST`, `actor_id = null` |
| GET | `/guest/orders/{id}` | status of its own orders only; polled every 5 s — **no stream for guests** |

A guest token never returns another session's data, any staff endpoint, any total other than its own
orders, or any payment information. Throttle 60 requests/min per session.

### Owner

| Method | Path | Notes |
|---|---|---|
| GET | `/reports/variance?from&to` | voids after ack (value, reason, actor, authoriser), discounts and comps by staff, reopened bills, cash variance by shift and cashier, order-number gaps |
| GET | `/reports/today` | `money_taken_pesewas`, covers, average bill, open bills now |
| GET | `/reports/patterns?from&to` | money taken by hour, payment method mix, best sellers by value, order-to-ready time per station |
| GET | `/events/log?actor_id&type&aggregate_type&from&to&cursor` | the stream, newest first, cursor by `seq`; each row has `flagged: bool` |

The word **"Money taken"** appears in the OpenAPI descriptions of every gross figure. Not "Revenue".

## 4. SSE stream format

```
id: 1047
event: ORDER_SUBMITTED
data: {"id":"0192…","seq":1047,"type":"ORDER_SUBMITTED","aggregate_type":"ORDER","aggregate_id":"0192…",
       "order_id":"0192…","actor_role":"WAITER","reason_code":null,"created_at":"2026-09-14T19:42:08Z",
       "payload":{"order_number":1047,"table_number":"9","items":[…],"total_pesewas":21600}}

: keepalive
```

- Reconnect with `Last-Event-ID: 1047` → server replays `seq > 1047` first, then live.
- Clients drop any envelope whose `seq` ≤ the last one applied.
- After two consecutive stream failures the client polls `GET /events?since=` every 3 s and retries the
  stream every 30 s.
- Payloads carry what a display needs to render **without a follow-up GET** (order number, table,
  lines with snapshots, station, totals). Reads are for cold start; the stream is for updates.

## 5. Reason codes

Free text is allowed as `note`; `reason_code` is one of a fixed list so the owner's report can group them.

| Purpose | Codes |
|---|---|
| Void | `GUEST_CHANGED_MIND` `WRONG_TABLE` `KITCHEN_ERROR` `ITEM_FINISHED` `DUPLICATE` `OTHER` |
| Discount / comp | `STAFF_MEAL` `OWNER_GUEST` `COMPLAINT` `PROMOTION` `LOYALTY` `OTHER` |
| Price override | `MENU_ERROR` `NEGOTIATED` `OTHER` |
| Reopen | `ADD_ITEMS` `WRONG_PAYMENT` `OTHER` |
| Drawer movement | `NO_SALE` `SUPPLIER_PAID` `CHANGE_FLOAT` `OWNER_WITHDRAWAL` `OTHER` |
| Payment void | `WRONG_AMOUNT` `WRONG_METHOD` `DUPLICATE` `OTHER` |

## 6. Smoke walk-through (`curl`)

```sh
API=http://localhost:8000/api/v1
K() { python -c "import uuid6;print(uuid6.uuid7())"; }

# 1. enrol the device (code from admin or `manage.py enrol_device`)
curl -s $API/devices/enrol -H "Idempotency-Key: $(K)" -d '{"enrolment_code":"ABCD-1234"}'
# → {"device_id":…,"device_token":"…"}
export DT=<device_token>

# 2. PIN login
curl -s $API/auth/pin -H "X-Device-Token: $DT" -H "Idempotency-Key: $(K)" -d '{"staff_id":"…","pin":"1234"}'
export ST=<token>
H=(-H "X-Device-Token: $DT" -H "Authorization: Bearer $ST" -H "Content-Type: application/json")

# 3. open a table, open an order, add an item, submit
curl -s $API/sessions "${H[@]}" -H "Idempotency-Key: $(K)" -d '{"id":"'$(K)'","table_id":"…","party_size":2}'
curl -s $API/orders   "${H[@]}" -H "Idempotency-Key: $(K)" -d '{"id":"'$(K)'","session_id":"…"}'
curl -s $API/orders/<oid>/items "${H[@]}" -H "Idempotency-Key: $(K)" -d '{"id":"'$(K)'","menu_item_id":"…","quantity":1,"modifier_ids":[]}'
KEY=$(K)
curl -s -i $API/orders/<oid>/submit "${H[@]}" -H "Idempotency-Key: $KEY" -d '{}'
curl -s -i $API/orders/<oid>/submit "${H[@]}" -H "Idempotency-Key: $KEY" -d '{}'   # → same body, Idempotent-Replayed: true

# 4. watch it arrive
curl -N $API/stream "${H[@]}"                       # in another terminal, before step 3
curl -N $API/stream "${H[@]}" -H "Last-Event-ID: 3" # reconnect: replays seq 4… in order
```
